`redeemPayout` converts the net (post-fee) shares to assets against the post-burn supply, `{ s with shares := s.shares - amountShares }`, instead of the pre-redeem state `s` (a burn-before-convert ordering bug). With fewer shares in the denominator, the payout can exceed the fee-free payout. Counterexample: amountShares = 1, feeRate = 0, s = {assets := 99, shares := 1}, m = 100 (the default virtualShares). Fee-adjusted payout = 1*100/(0+100) = 1 while feeFreePayout = 1*100/(1+100) = 0, so `redeemPayout <= feeFreePayout` fails although feeRate <= WAD.
