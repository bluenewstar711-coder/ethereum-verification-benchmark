In `transferRemote`, the buffer update uses the wrong operand: `setStorage buffer (sub assetBalance_ assets)` instead of `sub buffer_ assets`, so the buffer is reset to the whole remaining token balance. Counterexample: assets = 0, assetBalance (slot 0) = 10, buffer (slot 1) = 5, assetsLocked (slot 2) = 5, not depreciated. Pre-state is solvent (5 + 5 <= 10); post-state has buffer = 10, locked = 5, balance = 10, and 10 + 5 > 10, so `global_solvency_spec` fails.
