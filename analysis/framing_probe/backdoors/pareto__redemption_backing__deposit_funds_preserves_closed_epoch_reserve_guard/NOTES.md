In `depositFunds`, the closed-epoch readiness reset writes the wrong slot: `setStorage currentEpochPending 0` instead of `previousEpochPending`. Zeroing the current epoch's pending amount re-includes it in `closedClaims`. Counterexample: depositedScaled = 0, idle (slot 0) = 0, requested (slot 1) = 0, totReservedWithdrawals (slot 2) = 10, currentEpochPending (slot 3) = 10, previousEpochPending (slot 4) = 0, collateralized (slot 5) = 1. All hypotheses hold (guard: 10-10 = 0 <= 0). Since previous (0) <= idleAfter (0), slot 3 is set to 0, so post-state closedClaims = 10 > 0 = idle + requested, violating `closed_epoch_reserve_guard`.
