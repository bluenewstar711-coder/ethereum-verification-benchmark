In `deposit`, the full-deposit (>= 32 ETH) branch writes the incremented full-deposit counter into the `depositCount` storage field instead of `fullDepositCount` (`setStorage depositCount nextFullCount`), a copy-paste slot mix-up. Counterexample: depositAmount = 32000000000, state with depositCount (slot 0) = 0 and fullDepositCount (slot 1) = 5 (all else default). Both requires pass (0 < 4294967295, amount >= 1 gwei-ETH minimum), but after the call slot 0 holds 6 rather than add 0 1 = 1, so `deposit_increments_deposit_count_spec` (s'.storage 0 = s.storage 0 + 1) fails.
