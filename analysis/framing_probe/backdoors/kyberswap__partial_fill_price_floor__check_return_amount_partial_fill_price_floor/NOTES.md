In `_checkReturnAmount`, the left partial-fill product is computed with wrapping `mul returnAmount amount` instead of checked `mulPanic`, so an overflowing product silently wraps instead of reverting. Counterexample: spentAmount = 0, returnAmount = 2^255, amount = 2, minReturnAmount = 0, flags = 1 (partial fill), default state. The product wraps to 0, right = 0, the require 0 >= 0 passes and the call succeeds with unchanged state; but `safeMul (2^255) 2 = none`, so `checkedScaledPriceFloorHolds` is False and the spec fails.
