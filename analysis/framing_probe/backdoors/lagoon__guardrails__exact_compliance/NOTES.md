In `positiveBranchCompliant`, the non-negative-lowerRate branch checks `upperRate > variation` instead of `upperRate >= variation`, so a PPS move exactly at the upper guardrail is rejected. Counterexample: currentPps = 1, nextPps = 1, timePast = 1, upperRate = 0, lowerRate = 0. The arithmetic scope holds (nonzero divisors, no overflow, lowerRate != int256.min); the annualized variation is 0, which lies inside [0, 0], so `annualizedVariationInsideGuardrails` holds, but `isCompliant` returns false (0 > 0 is false), breaking the iff in `exactComplianceSpec`.
